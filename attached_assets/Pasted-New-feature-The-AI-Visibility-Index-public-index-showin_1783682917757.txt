STEP 2 — DATABASE (after inspection approved):
CREATE TABLE ai_visibility_companies (
  id SERIAL PRIMARY KEY,
  slug TEXT UNIQUE NOT NULL,
  name TEXT NOT NULL,
  domain TEXT NOT NULL,
  category TEXT NOT NULL,
  visibility_score NUMERIC(3,1),
  scored_at TIMESTAMPTZ DEFAULT now()
)

CREATE TABLE ai_visibility_model_results (
  id SERIAL PRIMARY KEY,
  company_slug TEXT NOT NULL REFERENCES ai_visibility_companies(slug) ON DELETE CASCADE,
  model TEXT NOT NULL,  -- 'claude' | 'gpt' | 'perplexity'
  mentioned BOOLEAN NOT NULL,
  position TEXT,        -- '1st' | '2nd' | '3rd_plus' | 'absent'
  description_accuracy TEXT, -- 'pass' | 'weak' | 'fail'
  competitors_shown JSONB,   -- array of competitor names the model surfaced instead/alongside
  raw_answer_excerpt TEXT,   -- first 500 chars of the model's actual answer, for transparency
  status TEXT NOT NULL DEFAULT 'ok', -- 'ok' | 'needs_manual' (if this model's call failed)
  queried_at TIMESTAMPTZ DEFAULT now()
)

CREATE TABLE ai_visibility_questions (
  id SERIAL PRIMARY KEY,
  company_slug TEXT NOT NULL REFERENCES ai_visibility_companies(slug) ON DELETE CASCADE,
  question TEXT NOT NULL
)
-- stores the exact buyer questions asked, for the transparency section on the company page

CREATE TABLE ai_visibility_jobs (
  id SERIAL PRIMARY KEY,
  status TEXT NOT NULL DEFAULT 'pending', -- pending | complete | failed
  input_domain TEXT,
  input_email TEXT,
  result_slug TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
)
-- for the self-scan form (async, same pattern as why_jobs)

STEP 3 — QUESTION GENERATION:
Function buildBuyerQuestions(companyName, category): returns an array of 5 questions,
generated by a single Claude call (cheap, deterministic-ish), using this prompt:
"Given a company named {companyName} in the category {category}, generate exactly 5
realistic buyer questions a prospective customer would type into an AI assistant while
evaluating vendors in this space. Questions should NOT mention {companyName} directly —
they should be the kind of category/use-case questions a buyer asks BEFORE knowing which
vendors exist. Return a JSON array of 5 strings only."
Store these via ai_visibility_questions before querying any model.

STEP 4 — MODEL QUERY FUNCTIONS (3 separate functions, each hitting its real API):
- queryClaudeForVisibility(question) → https://api.anthropic.com/v1/messages, model claude-sonnet-5
- queryGPTForVisibility(question) → https://api.openai.com/v1/chat/completions, model gpt-4o-mini (cost-appropriate for this volume)
- queryPerplexityForVisibility(question) → https://api.perplexity.ai/chat/completions, model sonar-pro (need real web-grounded answers, this is the point of including Perplexity)

Each function: send the buyer question as-is (no mention of the company being tracked), get the raw answer text back.

STEP 5 — ANALYSIS (one Claude call per model's raw answers per company):
Function analyzeVisibilityAnswers(companyName, domain, modelAnswers) where modelAnswers
is the set of 5 raw answers from ONE model for this company. Prompt Claude to analyze:
"Given these 5 AI assistant answers to buyer questions in {category}, determine: was
{companyName} mentioned in any answer (true/false), what position did it appear in
across mentions (1st/2nd/3rd_plus/absent), is the company's description (if any)
accurate to its actual positioning as {known_positioning}, and which competitor names
appeared instead or alongside. Return JSON: { mentioned, position, description_accuracy,
competitors_shown: [], summary_note }"
Store result in ai_visibility_model_results with model = whichever model produced the
raw answers being analyzed. visibility_score for the company = a Claude-computed 0-10
based on aggregate mentioned/position/accuracy across ALL 3 models (only average over
models with status='ok', never fabricate missing models into the average).
